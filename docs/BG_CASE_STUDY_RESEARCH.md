# B/G 端产品案例页：调研与可行性结论

更新时间：2026-08-12
适用页面：`?page=bg-product`
目标受众：招聘方、产品与设计专业从业者

## 1. 任务定义

为“新型负荷管理平台 II”建立一个可持续维护的作品案例框架。页面需要先承载项目叙事，后续可以替换成真实的界面截图、原型录屏或短视频；不以装饰性假素材替代项目证据。

## 2. 调研观察

本次比对了多类成熟作品集案例：

- Fábio Alencar 的 B2B Dashboard Redesign：强调改版前的业务上下文、任务流与设计取舍。
- Dawson Lee 与 Vadim Pronin 的产品案例：将“项目角色、范围、过程证据、结果”作为招聘方快速扫描的主线。
- MintSwift 的 SaaS 案例：用完整叙事连接问题、决策、界面与最终交付，而非仅展示界面拼图。
- UI 作品集公开案例的常见问题：一屏堆叠大量页面、没有问题定义、没有角色边界，招聘方难以判断贡献。

## 3. 方案对比

| 方向 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 界面图集优先 | 视觉冲击快 | 无法说明设计判断与实际贡献 | 不采用 |
| 业务叙事优先 | 便于招聘方判断能力边界，专业同行可追溯决策 | 需要约束文案长度与素材节奏 | 采用 |
| 大型互动 Demo | 表现力强 | 开发及维护成本高，缺少真实素材时会形成伪展示 | 当前不采用 |

## 4. 已选择的信息结构

1. 项目概览：项目名称、项目背景、角色、周期、类型与真实主视觉。
2. 业务问题：明确复杂业务中的信息、协同与执行问题。
3. 设计决策：以三项决策表达信息架构、过程可控、状态可见的设计思路。
4. 界面证据：展示实际平台界面，保留合规的内容遮罩与说明。
5. 媒体规划：明确后续适合替换的 16:9、4:3、9:16 素材和各自应该回答的问题。
6. 收尾：用可跳转回项目总览的链接结束，不虚构未验证的业务指标。

## 5. 视觉与交互准则

- 基调：白底、浅蓝色分区、专业蓝 `rgb(0 163 255)`，深墨蓝正文。
- 不使用暗色首页的星空、霓虹和重毛玻璃，避免项目页与首页争夺视觉注意力。
- 入场：页面内容以较慢的上移淡入出现；支持系统“减少动态效果”偏好。
- 滚动：采用现有 Lenis 平滑滚动，不额外添加复杂滚动劫持。
- 图片：必须配有说明文字；没有真实素材时展示“待替换媒体规划”，而不是伪造仪表盘或数据。

## 6. 素材替换约定

| 位置 | 推荐规格 | 内容目的 |
| --- | --- | --- |
| 项目主视觉 | 16:9，至少 1920×1080 | 交代产品场景和整体气质 |
| 核心界面证据 | 16:9 或 4:3 | 支撑任务流、信息层级或关键交互 |
| 原型视频 | 9:16 或 16:9，静音可循环 | 展示分步流程、状态反馈或微交互 |

替换图片时应同步更新 `alt` 文本与图注；涉及敏感业务、客户名称、账号或数据时，先脱敏后再发布。

## 7. V1 验收标准

- B/G 页面可通过 `?page=bg-product` 独立访问，且不会影响首页。
- 页面在桌面与移动端采用流式布局；窄屏下由双栏转为单栏。
- 导航在白底页面使用浅色毛玻璃变体，移动端展开菜单不再出现深色不协调面板。
- 至少展示一个真实主视觉与一个真实界面证据；其他内容不伪造成品。
- 不发布到正式环境，后续经人工视觉检查后再决定是否上线。
