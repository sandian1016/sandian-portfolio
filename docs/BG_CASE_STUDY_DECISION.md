# B/G 案例页最终设计决策

更新时间：2026-08-13
状态：进入本地实现，不部署正式环境

## 最终选择

采用“编辑式案例叙事 + 证据优先媒体框架”。

该方向不是站酷长图的直接复刻，也不是 SaaS 模板卡片。它把招聘方需要的快速判断放在上层，把专业设计者需要的约束、取舍和界面证据放在下层。

## 最终页面结构

1. **项目封面**：项目类别、英文副标题、核心问题、业务范围、真实主视觉。
2. **案例导航**：项目背景、设计决策、界面证据、交付反思四个锚点。
3. **项目背景**：问题边界、设计职责、业务对象、协作范围；不虚构项目周期。
4. **三次设计判断**：系统骨架、任务清晰度、设计规则，每章均预留对应证据。
5. **界面证据**：先展示已有真实页面，后续按图组和视频规格扩展。
6. **交付与反思**：明确已形成的设计输出、尚缺的数据验证和后续补证据方式。

## 为什么不选其他方案

- **不选长图画册**：视觉成果容易浏览，但无法证明个人贡献与判断逻辑。
- **不选卡片网格**：可维护但模板感强，难以形成项目的叙事节奏。
- **不选重交互演示**：真实素材尚未齐全，开发与性能成本高，且会影响移动端阅读。

## 内容规则

- 一个章节只证明一个核心判断。
- 每张图片必须回答“它证明了什么”，图注不写泛化形容词。
- 结果分为“已验证”和“待验证”，不把设计输出写成业务结果。
- 职责只陈述已有证据支持的范围：UI 交互、信息架构和设计规范。
- 项目周期待用户提供可靠信息后再加入。
